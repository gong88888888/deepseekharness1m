# Agent Note: 在压力压缩前预留对话输出

Status: implemented

[English](2026-09-10-compaction-output-reserve.md) | 中文

## Problem

仅依据总上下文窗口计算的输入压力阈值可能超过为生成预留空间后的输入容量。DeepSeek 适配器声明 1,000,000 token 窗口和默认 256,000 token 输出上限；80% 阈值留下的空间小于该输出上限。

## Decision

[基础压缩](../../../../packages/compaction/compaction-basic/README.zh.md) 将阈值解析为配置窗口比例与 `contextWindow - reservedOutputTokens - safetyMarginTokens` 中的较小值。输出预留来自最新持久请求头，其中已经解析适配器默认值。输出上限缺省时预留零。可配置的非负整数安全余量默认为零，并支持精确的提供方/模型覆盖。

保留策略保持显式：保留量必须低于有效阈值，不会通过自动削减历史掩盖矛盾配置。输入容量耗尽或保留量不兼容会抛出现有的目标压力配置错误。自动监听器保留告警后继续的行为；提供方溢出恢复仍有次数限制。

## Alternatives considered

**降低全局比例。** 固定的较低比例无法跟随不同输出上限或模型路由。

**使用摘要输出上限。** 该上限属于独立请求，不能用于预留对话响应。

**拒绝所有超过字符启发式预算的请求。** 这会混淆估算 token 与精确 token，并改变请求错误语义。本改动仅修正步骤间压力预算。

## Consequences

当输出分配需要更多空间时，长对话可以提前压缩。步骤间策略不能完全防止新输入接纳、后续路由变化、小窗口摘要提供方和启发式低估造成的问题。没有新增 Session 格式或事件。测试覆盖路由预留、安全余量、无效策略，以及低于比例阈值的大对话在持久输出上限增加后触发压缩。现有的溢出恢复录制组合也加载安全余量设置。
