# Agent Note: 保留消息来源并恢复 V2 Mnemon 摘要

Status: implemented

[English](2026-11-05-v2-mnemon-source-summary.md) | 中文

## 问题

使用 `dsh-mnemon` 写入的已发布 V2 会话包含这样的 `user/message` 来源：`kind: 'plugin'`、`plugin: 'dsh-mnemon'`、`form: 'instructions' | 'recall'`，并带有字符串 `summary`。冻结的 V0 来源校验器只允许通知形式携带 `summary`。V2 到 V3 的迁移复用了该校验器，因此历史会话无法打开。源 V2 文件未被修改；本机语料中有 25 份产物、共 67 条此类消息。

## 决策

V2 到 V3 的准入及 V3 关系恢复只对这一精确的 `user/message` 来源使用略去 `summary` 的私有校验视图，返回和产出仍保留原事件的摘要与内容。冻结校验器继续检查其余来源字段和消息字段。其他插件、消息位置、形式及非字符串摘要仍按原规则拒绝。V3 到 V4 将插件身份提升为 `plugin:dsh-mnemon`，保留原形式和摘要。

## 考虑过的替代方案

**改写 V2 文件或移除摘要。** 两者都会丢失已记录数据；已提交的代际文件不可变，摘要也仍是有用的展示元数据。

**将来源形式改为通知。** 虽然正文还在，但这会错误描述历史消息提供的是指令还是召回上下文。

**放宽冻结的 V0 校验器或所有插件来源。** 已观察到的问题只来自这一历史生产者。全局例外还会接纳其他格式和插件中未经审计的来源组合。

## 验证

聚焦迁移测试和 V4 目录测试覆盖两种形式、元数据与正文保留、原生重开，以及其他来源继续被拒绝。独立的免密钥 V2 Web 快照通过实际 Host 会话观察器读取一条已记录的 Mnemon 回忆消息。这增加一个历史会话角色，将语料上限从 13 调整为 14。只读的当前目录扫描成功恢复本机全部 41 份压缩会话产物，包括用户报错的 V2 会话，且没有改写文件；该产物恢复为含 648 条事件的 V4 会话。

## 后果

历史 Mnemon 指令和召回消息在本运行时可读，同时保留原有来源元数据。兼容例外只属于 V2 到 V3 读取器及其私有的 V3 关系视图，不会挂载或重新启用不兼容的 Mnemon 插件。
