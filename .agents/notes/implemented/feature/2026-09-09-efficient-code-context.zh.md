# Agent Note: 有界代码初始读取与独立 token 测量

Status: implemented

[English](2026-09-09-efficient-code-context.md) | 中文

## 问题

大型文件观察结果会保留在后续模型请求中，直到裁剪或上下文压缩。初始读取窗口与允许的最大窗口共用一个设置，使部署无法同时减少无意带入的上下文并保留主动的大范围读取。token 测量还会复制计价操作已经独立分配的位置节点。

## 决策

[文件系统工具](../../../../packages/fs/tool-fs/README.zh.md) 分别提供 `readDefaultLimit` 和 `readLimit`。未配置的默认值继承最大值。两者必须为正整数，且默认值不能超过最大值。schema 声明生效的默认值；结果分页和显式的大范围读取保留现有行为。较小默认值由部署选择，不会全局削减文件访问能力。

[token 计量器](../../../../packages/llm/token-meter/README.zh.md) 直接冻结新计价的标量节点，并单独复制保留的供应商用量。返回的每个测量结果仍独立且深度不可变。每次测量都会重新计算路由价格；此修改不引入计价缓存或会话格式变更。

## 考虑过的替代方案

**降低最大读取大小。** 即使模型明确需要更大的连续区域，较小上限仍强制增加工具轮次。独立默认值保留该选择。

**提前裁剪观察结果。** 重写保留的历史可能丢失证据或使请求前缀复用失效。有界初始读取在多余输出进入持久化记录前减少它。

**缓存完整 token 测量结果。** 动态路由计价和请求时文件投影可能在没有新会话事件时变化。移除重复复制可保留这些依赖，无需引入缓存失效机制。

## 影响

部署可减少初始读取输出，同时保留分页、修改前观察校验和显式的大窗口。需要完整文件的任务若逐页采用默认窗口而不主动请求更大的范围，可能增加调用次数。测量复杂度仍与保留节点数线性相关；它本身不会降低供应商推理延迟或计费 token。

## 测试

文件系统定向测试覆盖省略 limit、连续读取、显式大窗口、超过上限及无效配置。[会话回放用例](../../../../snapshots/session/fs-read-default-window/snapshot.yml) 固定配置后的 schema 和分页结果。token 计量器测试覆盖独立不可变的测量结果和动态路由重新计价。[本地基准](../../../../scripts/benchmark-code-efficiency.ts) 无需供应商调用即可测量合成节点计价和读取输出；其基于字符的 token 估算不能证明端到端任务节省。
