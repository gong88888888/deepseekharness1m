# Agent Note: 显式任务效率控制

Status: implemented

[English](2026-09-09-task-efficiency-controls.md) | 中文

## 问题

庞大的工具目录和重复观察会增加模型输入，却不一定提高任务完成能力。现有会话聚合计时将准备工作与模型延迟合并，而独立工作流的限制不能约束同一引擎实例同时运行的工作流数量。

## 决策

[呈现插件](../../../../packages/core/agent-tool-presentation/README.zh.md) 可从准入目录按需发现原生工具定义。成功写入日志的发现结果决定已加载集合，请求头记录对应定义。选择器改变呈现方式而不授予执行权限。插件重新加载后，已加载名称的顺序保持稳定。

[网页工具](../../../../packages/web/tool-web/README.zh.md) 可在字节、数量和时间上限内复用调用者本地结果。抓取窗口标明抓取时间及字符偏移。续读要求同一版本仍被保留；供应商注册发生变化时缓存失效，每次查找均检查当前供应商可用性。供应商截断仍对调用者可见。[作业工具](../../../../packages/jobs/tool-jobs/README.zh.md) 可省略重复最终输出，同时保留显式恢复和现有流式游标。

[统计插件](../../../../packages/session/session-stats/README.zh.md) 可写入有上限、不含消息正文的本地计时记录。写入过载或失败不延迟任务执行。[工作流引擎](../../../../packages/workflow/workflow-ptc/README.zh.md) 支持实例级运行数量上限，[工作流工具](../../../../packages/workflow/tool-workflow/README.zh.md) 可提供更小的单次运行子任务预算，包含重试。

前台[子任务调用](../../../../packages/subagent/tool-subagent/README.zh.md)可请求供应商验证的结构化结果。不支持的供应商和无效模式在创建子任务前报错；携带模式的请求由调用方接收结果并等待子任务完成。通过已发布 profile 的无密钥会话场景覆盖工具发现、缓存网页续读与刷新、最终输出恢复、结构化子任务结果及受限工作流执行。

## 考虑过的替代方案

**通过过滤执行权限减少定义。** 工具发现改变展示内容，权限继续独立决定准入。混合两者会使被省略的工具无法安全地被发现。

**跨调用者缓存且不提供时效信息。** 此类复用会隐藏观察时间，并可能混合不同会话或供应商代次。调用者本地保留牺牲部分命中率，换取记录的取回时间、缓存命中状态和可预测失效。

**自动重试失败工作。** 子任务失败后可能留下文件或外部副作用。显式预算与结构化验收指导保留调用者在重试前检查部分结果的责任。

## 影响

所有控制均需显式启用。首次加载工具可能增加模型轮次，并使部分请求前缀复用失效。网页内容淘汰后，续读会报错，而不是静默抓取另一个版本。计时记录测量扩展点区间和 token 计数，不虚构单独的网络、操作系统启动或金额计量。容量拒绝会阻止额外 worker 启动，但不会对已完成任务去重。已发布的 Session 代次保持不变。
